### Objetivo

Garantir que o agente WhatsApp opere de forma segura, com rate limiting por número de telefone, log de auditoria de interações, validação de status do usuário, tratamento de payload inválido e proteção contra números não vinculados.

### Escopo

**Inclui:**
- `whatsappSecurityService.js` — novo módulo de segurança com:
  - `checkRateLimitPorNumero(telefone)` — in-memory rate limit (Map + timestamp), máximo 20 mensagens por minuto por número
  - `registrarLogWhatsapp(...)` — salva no `WhatsappLog` do Prisma (fire-and-forget)
  - `validarUsuarioAtivo(usuario)` — retorna booleano e mensagem de erro amigável
- Integração dos checks de segurança em `whatsappService.js`:
  - Verificar rate limit por número ANTES de qualquer processamento
  - Ignorar mensagem com `text` vazio (sem resposta, sem log, return silencioso)
  - Logar toda mensagem recebida e toda resposta enviada
  - Logar tentativa de número não vinculado com `status: 'sem_usuario'`
  - Bloquear usuário inativo com resposta: `⛔ Sua conta está suspensa. Entre em contato com o suporte.`
- Testes unitários para o novo `whatsappSecurityService.js`
- Testes criados para `whatsappService.js` cobrindo os novos fluxos

**Não inclui:**
- Rate limiting distribuído (Redis) — mantém in-memory no MVP
- Criptografia adicional de mensagens
- Autenticação via PIN/OTP pelo WhatsApp
- Múltiplos canais

### Fluxo de segurança implementado

```
Mensagem recebida
    → fromMe? → return silencioso
    → text vazio? → return silencioso (sem log)
    → checkRateLimitPorNumero(from) → bloqueado? → log rate_limited + return
    → identificarIntent(text)
    → UNKNOWN? → enviar help menu + log entrada + log saída + return
    → resolverUsuarioPorWhatsapp(from)
    → não encontrado? → log sem_usuario + enviar orientação + return
    → validarUsuarioAtivo(usuario)
    → inativo? → log usuario_inativo + enviar mensagem suspensa + return
    → log entrada
    → executarAcao(usuario, intent, params)
    → enviarMensagem(from, resposta)
    → log saída
```
